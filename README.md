# dekopon-provider-chat

A Wasm provider for explicit, broker-scoped text history reads. It does not change automatic platform recall. Its `chat.slack.history.read` capability serves `chat slack get last N`, where `N` is an integer from 1 to 100. `chat send` and arbitrary channels, thread IDs, workspace IDs and URLs are not accepted. The provider does not expose file bytes or post messages. Discord support is a later source step.

An authorized call emits one JSON object with `messages` (oldest first) and `truncated` (true when Slack reports more history after the request budget). Each message has `id`, raw platform `author`, `time`, `text` and `assets`; each asset has `id`, `name`, `mime`, `size` (null when absent) and `available:false`. File references are descriptive only; there is no asset-import capability. Empty authorized history returns `{"messages":[],"truncated":false}`. Permission, throttling, unavailable history, malformed data and failed pages return nonzero errors, not empty success. Body size is bounded after HTTP decoding; two pages at most.

The provider sends GET `https://slack.com/api/conversations.replies?limit=N` (and, on a second page, `cursor`). **It does not send `channel` or `ts`.** The owner must attach one broker request template pinning `channel: conversation.id` and `ts: conversation.thread` to the attested `ChatScopeClaim`, allowing only `limit` and `cursor`. [The offline fixture](tests/fixtures/broker.yaml) shows the required host, request budget, method and template. Without a claim/thread slot, broker invocation refuses before HTTP; a Classic-mode DM without a thread cannot use this capability. Agent-mode DMs and channel roots with a root thread slot can read only that root via replies, never `conversations.history`. A provider manifest alone is *not* authorization: the broker's credential, constraint set and Cedar grant remain separate owner actions. The example credential in tests is synthetic and must never be deployed.

To validate locally, use the [agent guide](AGENTS.md) gates and `python3 tests/verify_broker.py` with brokerd 0.47.0 on `PATH` or `DEKOPON_BROKERD=<path>`. That script uses private temporary files and terminates its own test broker; it never contacts Slack. `dekopon-brokerd check` intentionally does not read credentials: it checks static templates/metadata and warns that credential binding is verified at boot. Boot rejects credential/host mismatches.
